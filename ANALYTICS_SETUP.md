# Analytics Setup Guide

This website is a static HTML site deployed on Netlify at
`https://apexps.netlify.app`. Analytics installation requires a future code
change to the page `<head>` sections. This guide does not install tracking
scripts or change the deployed site.

## Before Installing Tracking

- Decide who owns the Google Analytics and Microsoft Clarity accounts.
- Confirm any consent banner and privacy notice requirements for the regions
  where visitors are measured before enabling tracking.
- Use only production tracking code copied from the account created for Apex
  Power Systems. Do not commit sample or guessed identifiers.

## Add Google Analytics 4 (GA4)

1. Sign in to [Google Analytics](https://analytics.google.com/) with the
   business-owned account.
2. Create or choose the Apex Power Systems GA4 property.
3. Under **Admin** > **Data streams**, create or open a **Web** stream for
   `https://apexps.netlify.app`.
4. Open **View tag instructions** > **Install manually**.
5. Copy the entire Google tag generated by Google for that web stream. Its
   Measurement ID is displayed in the stream details and normally begins with
   `G-`.
6. In a dedicated implementation change, insert the copied Google tag
   immediately after the opening `<head>` tag on every public HTML page.

The GA4 manual installation instructions are maintained by Google:
[Set up Analytics for a website and/or app](https://support.google.com/analytics/answer/9304153).

## Add Microsoft Clarity

1. Sign in to [Microsoft Clarity](https://clarity.microsoft.com/) with the
   business-owned account.
2. Create or select the project for `https://apexps.netlify.app`.
3. Go to **Settings** > **Setup**, choose manual installation, and select
   **Get tracking code**.
4. Copy the complete project-specific tracking code generated by Clarity.
5. In the implementation change, paste that code into the `<head>` section of
   every public HTML page, together with the GA4 tag if both tools are enabled.

Microsoft's current manual setup steps are documented at
[Setup Clarity](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-setup).

## Where Tracking Code Goes in This Repository

This project serves HTML files directly and does not use a shared layout
template or a build step. Tracking tags therefore need to be included in every
public page that visitors can open, including:

- Root pages such as `index.html` and `404.html`.
- Section pages such as `about/index.html`, `contact/index.html`,
  `products/index.html`, and `solutions/index.html`.
- Individual product and solution pages under `products/*/index.html` and
  `solutions/*/index.html`.

For GA4, follow Google's instruction to paste the generated Google tag
immediately after the opening `<head>` tag. For Clarity, place the generated
tracking code in the same `<head>` section. Keep each provider's code unchanged
from the version shown in its dashboard.

## Avoid Fake Placeholder IDs

- Do not commit examples such as a made-up GA4 Measurement ID or a made-up
  Clarity project ID.
- Do not copy a tag from a tutorial, staging site, or another company project.
- Copy the full generated snippet from the production GA4 web stream and from
  the production Clarity project only when the implementation is ready.
- Before merging an implementation pull request, search the diff for tracking
  IDs and confirm them against both service dashboards.
- If the real IDs are not available yet, merge documentation only and leave
  tracking uninstalled until the account owner supplies the generated code.

## Verify Tracking After Deployment

1. Merge the implementation pull request and wait for the Netlify production
   deploy to complete successfully.
2. Open `https://apexps.netlify.app` in a fresh browser window with ad blockers
   disabled for the verification visit.
3. In GA4, open **Reports** > **Realtime** and confirm that the visit or page
   view appears. Google notes that initial data collection can take up to
   30 minutes.
4. Navigate to several pages and confirm their page paths appear in GA4 rather
   than only the home page.
5. In Clarity, open the Apex project dashboard and confirm that new visit data
   begins appearing. Confirm that sensitive form inputs are masked as expected
   before relying on recordings.
6. If either service remains empty, inspect the deployed page source to ensure
   that the real generated tag is present in `<head>`, check browser network
   requests for blocked analytics calls, and re-check that the deployed tag
   belongs to the correct production property or project.

For additional GA4 verification guidance, see
[Confirm that you're collecting data](https://support.google.com/analytics/answer/9333790).

## Redeploy Through Netlify After Merging

The Netlify project is configured to publish this static repository from the
`main` branch with publish directory `.`.

1. Create a pull request containing the approved tracking-code changes.
2. After review, merge the pull request into `main`.
3. Netlify's Git-connected deployment should automatically build and publish
   the new `main` commit.
4. In Netlify, open the site's **Deploys** view and confirm the production
   deployment for the merge commit is successful.
5. If an automatic deploy must be retried, use **Deploys** > **Trigger deploy**
   > **Deploy site**, then repeat the verification steps above.

Netlify deployment reference:
[Create deploys](https://docs.netlify.com/deploy/create-deploys/).
